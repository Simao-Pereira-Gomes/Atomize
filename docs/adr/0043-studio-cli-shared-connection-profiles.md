# Studio and CLI share Connection Profile records

Atomize Studio and the CLI share `~/.atomize/connections.json` for Azure DevOps Connection Profile metadata and per-platform defaults, while each uses its native credential API against the same OS-keyring service/account convention (`atomize` / profile name). Studio manages profiles through Rust Tauri commands, never through the sidecar; it supports only keyring-backed tokens, so a CLI profile using the insecure keyfile fallback must be rotated before Studio can use it. Both clients honor a shared lock-file protocol for profile mutations. This preserves one interoperable profile inventory without coupling Studio to the CLI's Node/keytar implementation; add, rotate, and remove compensate or report retryable cleanup failures to avoid leaving a stored profile unusable.

**Considered:** independent Studio storage — rejected because users would maintain incompatible profile inventories. Letting Studio implement the CLI's encrypted keyfile fallback — rejected because it expands Studio's credential surface and still does not share the CLI's keytar implementation. Sidecar-owned profile operations — rejected because the sidecar must not access OS credentials.
