# Studio Back moves to a global navigation history stack, decoupled from discarding the Authoring Store

`StudioShell` has no navigation stack: `activeArea` and `surface` are flat signals, and every "back" affordance is a hardcoded jump wired independently per screen. `AtomizeStudio`'s "← Back to starting paths" button conflates two unrelated things in one action — it always calls `stores.reset()` *and* sets `surface` to `"starting-paths"`, regardless of where the user actually came from. For Catalog Clone specifically (ADR-0050), this means Back never returns to the Catalog Area the clone originated from; it discards the cloned Template and jumps past Catalog straight to `StartingPathPicker`, even though switching Studio Areas everywhere else is explicitly non-destructive ("Studio Areas are independent and switching between them does not reset in-progress authoring state, by design" — ADR-0050). `StartingPathPicker`'s AI-draft tile has its own separate, independently-hardcoded local back toggle, duplicating the same pattern a second time.

**Decision:** `StudioShell` gains a single, global navigation history stack recording both Studio Area changes and `surface` transitions (Starting Paths ↔ Builder) — the two things a user perceives as moving between screens. One persistent Back control (near the sidebar, disabled when the stack is empty) replaces the builder's and the AI-draft sub-form's separate back buttons; it pops the stack and never touches the Authoring Store, matching how Studio Area switches already behave. Discarding the in-progress Template becomes its own explicit action, no longer a side effect of navigating: it clears the Authoring Store and resets the navigation stack to a fresh Starting Paths root, rather than pushing a history entry, since a stack entry pointing at a Builder screen whose backing Template no longer exists could never be meaningfully restored. Every Starting Path that replaces the Authoring Store's content the same way an explicit discard does — Scratch, Catalog Clone, Open, and AI draft (all call `stores.reset()`/`stores.loadTemplate()`) — resets the stack on the same terms, so no path leaves a dangling entry pointing at destroyed state. New navigation after a Back truncates whatever was ahead in the stack, matching browser semantics, but no Forward control is exposed — nothing in the current flows needs it. Builder Sections (Basic Info, Filter, Tasks, Estimation, Validation, Metadata, Review) and the AI-draft tile's own idle/generating toggle stay out of the stack; they remain local, surface-internal state rather than navigable screens.

This design also fixes a latent bug the old always-discard Back accidentally masked: `requestCatalogClone`'s overwrite guard (ADR-0050) decides whether to show a discard confirmation by checking `surface() === "builder"`. Once Back can leave the Builder without discarding, a user can hold an unsaved Template in the Authoring Store while `surface` is no longer `"builder"` — for example, after backing out to the Catalog Area — and the guard would silently miss it, letting a second Clone overwrite the first with no warning. The guard must check whether the Authoring Store actually holds unsaved content, not the current `surface` value.

**Considered:** tracking only a single "point of origin" per Builder entry instead of a full stack — rejected in favor of a stack up front even though the current screen graph is only two levels deep (Starting Paths/Catalog → Builder), since a point-of-origin pointer would need replacing the moment any future flow adds a third hop, and the stack costs little more to build now. Including Section switches and the AI-draft toggle in the stack — rejected as the same category error the old design already made once: not every state change is a navigable "screen," and treating tab clicks as back-able would make the global Back control fire on trivial in-page interaction. Adding a Forward control alongside Back — rejected as unrequested surface area; browser-style Forward assumes a use case (deliberately un-doing a Back) that hasn't come up here.
