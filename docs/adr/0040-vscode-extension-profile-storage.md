# VS Code extension owns independent profile storage, with one-time CLI import

> Reverses ADR-0012's "the extension does not read Atomize connection files or credential storage directly; the CLI is the source of truth for profile state" — that premise depended on `auth list --json` as a subprocess call, which ADR-0038 removes entirely.

ADR-0038 established that the extension embeds `atomize-core` and resolves each Connection Profile's secret through `vscode.ExtensionContext.secrets`, but left open how the extension discovers and stores a profile's non-secret fields (name, organizationUrl, project, team) now that `atomize auth list --json` no longer exists as a discovery API.

**Decision:** the extension owns a fully independent profile store — non-secret fields in `ExtensionContext.globalState`, secrets in `SecretStorage`, both keyed by profile name — with zero ongoing coupling to the CLI's `~/.atomize/connections.json`. The only bridge is a one-time, explicitly-invoked "Import from CLI" action, surfaced solely in the profile picker's empty state (no extension-owned profiles yet, and at least one profile found in `~/.atomize/connections.json`). It reads that file defensively and read-only — never writes to it — to pre-fill name/organizationUrl/project/team per CLI-known profile; the user re-pastes the PAT once per import. After that, the imported profile is indistinguishable from one created directly in the extension.

**Considered:** continuous live-merging of `connections.json` into the profile picker on every open — rejected because the only benefit (skip retyping organizationUrl/project/team) is a one-time, transitional need for users who already had CLI profiles before upgrading, not an ongoing sync requirement; paying for a third profile-picker state and per-open defensive parsing bought nothing lasting. Having the extension decrypt the CLI's keytar/keyfile-encrypted token to migrate secrets too — rejected: it would require bundling `keytar` (a native module) into the extension, which cuts against #142's package-size/activation-time budget and against ADR-0038's choice of `vscode.ExtensionContext.secrets`. Forcing full manual re-entry with no import path at all — rejected as needlessly painful for the common case of an existing CLI user adopting the extension.
