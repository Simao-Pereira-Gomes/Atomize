# Catalog storage root and project discovery

Catalog items should be stored under `catalog` rather than a nested `templates/templates` root: user items in `~/.atomize/catalog/{templates,mixins}` and project items in `<workspace>/.atomize/catalog/{templates,mixins}`. Project scope resolves from a discovered workspace root (nearest ancestor containing `.atomize/`, then nearest git root, then current working directory) instead of raw `process.cwd()`, so running Atomize from a subdirectory does not accidentally create a separate project catalog. During migration, the CLI reads legacy `~/.atomize/templates/{templates,mixins}` and `<workspace>/.atomize/templates/{templates,mixins}` paths but writes only to the new `catalog` paths, with precedence `project catalog > project legacy templates > user catalog > user legacy templates > builtin`.
